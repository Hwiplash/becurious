# M9 UI 고객 모집단 일치 수정

감사 기준: 2026-09-20, `problem-region-handoff` 브랜치, 시작 커밋 `8bc5a93`.
시작 시 Git 작업트리는 깨끗했고 적용되는 AGENTS.md는 발견되지 않았다. 커밋·푸시는 하지 않았다.

## 발생 위치와 수정

`src/data.py:prepare`는 성별·연령 코드를 읽었지만 개인 필터를 적용하지 않았다. `app.py`는 이 원본 전체를 지역별로 자른 뒤 `src/charts.py:monthly_trend`에 전달했고, 차트는 `amt/cnt`를 조건 없이 월별 합산했다. 같은 원본이 상단 합계·건당금액·변화율·강점/약점 설명에도 쓰였다.

확인한 체크아웃에는 문제지역 JSON을 읽는 코드나 M9 예측밴드 구현이 없었다. 따라서 이 버전에서 확인한 문제는 전 코드 실제값 경로와 JSON 연결 부재다. 기존에 실행 중인 별도 배포본에서 밴드가 표시됐는지는 이 저장소 감사로 확인할 수 없다.

시군구 비교 화면은 이제 `handoff/problem_regions/problem_regions.jsonl`의 한 지역 객체에서 업종·월을 선택한다. 전체 업종 버튼은 `core9`, 개별 버튼은 9개 분석 업종코드에 대응한다.

| 화면/지표 | 최종 데이터 경로 |
|---|---|
| 실제금액·실제건수 | 같은 월 행의 `actual_amt`, `actual_cnt` |
| 기본 기대선 | `pi_center_amt`, `pi_center_cnt` |
| 90% 예측구간 | `lower90_amt/cnt`, `upper90_amt/cnt` |
| 진단 비율 | `I_amt`, `I_cnt` 그대로 표시 |
| 진단 기대값·실제와의 차이 | `expected_amt/cnt`, 같은 행의 실제−기대 |
| 하단 이탈 | 기존 `below90_amt/cnt` 유지 |
| 상단 이탈 | 개인 실제값과 같은 행의 상한 비교, 가용값만 표시 |
| 거래 경로·건당금액비 | `amount_count_ticket_path`, `ticket_ratio` 그대로 표시 |
| 건당금액·전월비 | 같은 JSON 실제/기대값에서 계산, 미관측 전월은 결측 |
| 문제지역·업종 최종 판정 | `region_status`, `industry_signals`, `final_signals` 유지 |

`expected_*`는 반복 OOF 평균이고 `pi_center_*`는 구간 중심이므로 서로 교체하지 않는다. 차트 범례와 설명에 차이를 명시하고 진단 기대값 선은 범례에서 별도로 켤 수 있다. 전체 9업종 구간은 JSON의 독립 합계모형 값을 사용하며 개별 구간을 더하지 않는다.

미관측 실제값은 null을 유지하고 실제선을 연결하지 않는다. 부분관측 추론 구간·외삽·보정 경고는 JSON대로 표시한다. JSON이 없는 지역은 비교 자료 없음으로 표시한다. 기존 서비스 JSON은 6개월 미완전 업종의 실제값까지 비워 둔 과거 스키마이므로, 부분관측 실제값·밴드가 보강된 최신 handoff JSON을 UI 권위 원천으로 선택했다.

원본을 쓰는 시군구 업종·성별·연령 보조차트 및 정책 설명의 소비는 `personal_consumption`으로 개인 9업종·2026년 1~6월로 제한한다. 코드 공백·대소문자·숫자형을 정규화한 뒤 성별 1/2, 연령 1~6을 적용한다. 정책 설명에는 선택 지역·업종의 기존 M9 JSON도 전달하며 외부 모델 호출 없이 모의 검증했다.

전국·시도 및 전국 업종 현황은 전 코드 기준을 유지하고 “전체 BC카드 이용금액”으로 구분한다. 기존 상권 지수는 별도 참고 영역에 유지한다. 현재 워크스페이스에는 UI가 요구하던 과거 지수 파일이 없으므로 지수 파일을 선택 입력으로 바꾸고 원본·문제지역 JSON만으로도 화면을 열도록 했다. BC 기본 경로에도 실제 프로젝트의 `../data/ABP_CONTEST_DATA.csv`를 추가했다.

## 검증

`tests/test_population.py`에 독립 원본 집계, 데이터 계약 및 Streamlit 화면 선택 검증을 추가했다.

최종 결과: 10개 테스트 통과(전수/선택 검증 8개 일괄 실행, 추가한 전국 업종 전환·정책 컨텍스트 2개 개별 실행). Python 6개 파일 구문 검사와 `git diff --check`도 통과했다.

- 문제지역 JSON 월별 16,566행 전체 검사. 실제값 가용 16,184행(개별 9업종 13,174행, core9 1,506행, 외식 합계 1,504행)의 금액·건수를 원본 개인 집계와 대조했다.
- 기존 서비스 JSON 월별 15,060행 전체 검사. 실제값 가용 14,634행은 원본 개인 집계와 일치하고, 가용 기대값은 handoff JSON과 일치한다.
- 251지역 × 10선택의 데이터 경로, 실제·기대·구간·하단 이탈·비율·경로 유지 확인.
- 전체 업종 실제값은 관측된 9개 업종의 개인 실제값 합계와 일치. 미관측 개별 업종 380행은 실제값 null이며 원본에서도 관측 행이 없다.
- 성별 3/X, 연령 X, 제외 업종의 큰 금액을 넣은 오염 검증, 숫자·문자 코드 변형 검증 통과.
- 부분관측 밴드, 미관측 실제선 공백, 미관측 월 전후의 전월비 결측, 동일 이름 지역 분리 확인.
- 두 고성군에서 전체+9개 업종 버튼, 금액/건수 전환, 시도/시군구 화면, M9 대상 밖 지역의 안내 확인.
- 전국 업종 모드 전환 및 정책 설명 JSON 연결도 추가 화면 테스트로 통과했다. 정책 생성·검색은 모의 함수로 대체해 외부 호출하지 않았다.
- 원본·기존 서비스/전달 데이터 20개 파일의 실행 전후 SHA-256 동일. JSON 후보 90지역·최종 신호 101개 유지. 모형 재학습·JSON 재산출·구간 변경 없음.

재현 명령(저장소 루트):

```powershell
.venv/Scripts/python.exe -B -X utf8 -m unittest discover -s tests -p test_population.py -v
```

비교 허용 오차는 JSON 부동소수점 직렬화 때문에 금액 0.01원, 건수 0.00001건이다. 정수 원본을 반올림하거나 보정하지 않는다. 화면은 Streamlit AppTest로 실행·선택·출력값을 확인했으며 브라우저 픽셀 검증은 별도로 수행하지 않았다.

## 변경 파일과 남은 해석 범위

`app.py`, `src/data.py`, `src/charts.py`, `src/problem_ui.py`, `src/policy_ui.py`, `handoff/problem_regions/README.md`, `tests/test_population.py`, 이 보고서.

지역 최종 판정은 외식 합계/특정 외식업종의 기존 판정이다. core9 또는 장보기 업종의 판정으로 확대하지 않는다. 미관측은 소비 0이나 점포 0을 뜻하지 않는다. 부분관측 집단에서 90% 포함률이 따로 검증된 것은 아니다. BC 소비는 전체 카드시장이나 지역 전체 매출이 아니며, 낮은 실제/기대비율만으로 원인·정책 문제를 확정하지 않는다.

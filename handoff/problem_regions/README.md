# 문제지역 분석 결과 전달 파일

이 폴더는 UI와 LLM에 연결할 최종 외식 문제지역 분석 결과다. 앱 코드는 포함하지 않으며, 화면과 정책 제안 로직에서는 이 파일들을 읽어 사용하면 된다.

## 파일 구성

| 파일 | 용도 |
|---|---|
| `region_index.json` | 지도, 지역 목록, 후보 필터에 쓰는 251개 시군구 요약 |
| `problem_regions.jsonl` | 시군구별 상세 진단. 한 줄이 한 지역인 JSONL 형식 |
| `sample_region.json` | 최종 후보 지역 한 곳의 상세 객체 예시 |
| `problem_region.schema.json` | 상세 객체의 JSON Schema |
| `manifest.json` | 분석 버전, 원천 파일 해시, 후보 수, 지도 조인 주의사항 |
| `source_audit.json` | 원천별 열, 결측, 조인 감사 결과 |
| `validation_summary.json` | 자동검증 결과 |

## 기준 결과

- 분석 기간: 2026년 1~6월
- 전체 지역: 251개 시군구
- 최종 후보: 90개 시군구
- 최종 신호: 101개
- 외식 전반 저조형: 지역 내 외식업종 대부분에서 기대보다 낮은 소비가 함께 이어진 경우
- 특정 업종 저조형: 지역의 외식 소비 전체가 낮은 것은 아니지만 일부 외식업종에서 저조가 뚜렷한 경우
- 모든 최종 후보는 월별 지속성과 반복 검증을 통과했으며, 일부 후보는 예측구간 기준까지 충족했다.

최종 후보 여부는 `region_status.is_final_candidate`만 사용한다. 다른 분석에서 생성된 `is_candidate` 필드나 임계값을 다시 적용하지 않는다.

분석 재현을 위해 JSON에는 내부 코드가 남아 있다. UI와 LLM 답변에서는 내부 코드를 그대로 보여주지 않고 다음 표현을 사용한다.

| JSON 내부 값 | 화면·답변 표현 |
|---|---|
| `F1_food_wide_low` | 외식 전반 저조형 |
| `F2_industry_specific_low` | 특정 업종 저조형 |
| `Tier A` | 예측구간까지 확인 |
| `Tier B` | 지속성과 반복 안정성 확인 |
| `Tier C` | 경향은 있으나 지속성 또는 반복 안정성 부족 |
| `Hold` | 자료 범위나 비교 조건의 추가 확인 필요 |
| `No signal` | 현재 기준에서 최종 신호가 확인되지 않음 |

## 공통 키

지역 조인 키는 다음 형식이다.

```text
시도|시군구
```

예시는 `광주광역시|북구`다. 현재 앱의 원본 소비데이터와 연결할 때는 다음처럼 만든다.

```python
region_key = df["SIDO_NM"].str.strip() + "|" + df["CCG_NM"].str.strip()
```

행정구역명을 유사 문자열로 자동 보정하지 않는다. 지도 경계와 이름이 일치하지 않는 지역은 `manifest.json`의 `geometry_missing`에서 확인한다.

## UI 연결

초기 화면과 지도에는 `region_index.json`을 사용한다.

- 후보 여부: `is_final_candidate`
- 판정 유형: `candidate_types`를 위 표의 자연어 표현으로 변환
- 검증 수준: `confidence_tier`를 위 표의 자연어 표현으로 변환
- 최종 신호 수: `final_signal_count`
- 기대 대비 금액: `amount_ratio`
- 기대 대비 건수: `count_ratio`
- 기대금액과의 차이: `shortfall_amount`
- 금액·건수·건당금액 경로: `amount_count_ticket_path`

사용자가 지역을 선택하면 같은 `region_key`를 가진 `problem_regions.jsonl` 한 행을 조회한다.

상세 화면에서 주로 사용할 영역은 다음과 같다.

- `region_status`: 최종 후보 여부와 판정 유형
- `food_aggregate`: 외식 합계의 실제·기대 금액과 건수
- `final_signals`: 최종 외식 전반·특정 업종 신호
- `industry_signals`: 외식업종별 구조보정 결과
- `monthly`: 전체 9개 업종·전체 업종 합계·외식 합계의 월별 실제·기대 소비와 90% 예측구간
- `customer_composition`: 연령·성별 결제 구성
- `grocery_context`: 장보기 업종과의 동반 저조 여부
- `model_warnings`: 보정과 해석 시 주의사항
- `interpretation_boundary`: 화면과 LLM에 함께 전달할 해석 한계

값이 없는 경우는 JSON `null`이다. `null`을 숫자 0으로 바꾸지 않는다. 금액 단위는 원, 거래건수 단위는 건이다.

### 월별 그래프와 예측구간 밴드

모든 지역 객체의 `monthly`에는 지역당 66개 행이 있다. 구성은 `core9` 전체 업종 합계 6개월, 외식 합계 6개월, 9개 개별 업종 54개 행이다. 따라서 251개 지역 전체에는 16,566개 월별 행이 존재한다.

| scope | 화면 표시 |
|---|---|
| `core9` | 전체 업종(9개) |
| `4004` | 대형할인점 |
| `4010` | 편의점 |
| `4020` | 슈퍼마켓 |
| `8001` | 일반한식 |
| `8004` | 일식회집 |
| `8005` | 중국음식 |
| `8006` | 서양음식 |
| `8021` | 스넥 |
| `8301` | 제과점 |

관측되지 않은 지역×업종×월 조합도 행을 유지한다. 이 경우 `data_available=false`, 실제·기대값과 구간값은 `null`이며 0으로 바꾸지 않는다.

월별 실제금액·건수 선에는 `actual_amt`, `actual_cnt`를 사용한다. 90% 예측구간 밴드는 각각 `lower90_amt`~`upper90_amt`, `lower90_cnt`~`upper90_cnt`를 사용하고, 밴드 중심선은 `pi_center_amt`, `pi_center_cnt`를 사용한다. `scope=core9` 행을 사용하면 시군구별 전체 9개 업종 합계의 월별 상·하한을 그릴 수 있다. 전체 업종 구간은 개별 업종 상·하한의 합이 아니라 별도 합계모형에서 산출한 값이다. 기존 `expected_amt`, `expected_cnt`는 반복 OOF 평균이므로 구간 중심과 정확히 같지 않다.

밴드는 실제값이 아니라 구간 중심을 둘러싸도록 그린다. `prediction_interval_available=false`이면 밴드를 표시하지 않으며, `calibration_ok_amt` 또는 `calibration_ok_cnt`가 거짓이면 툴팁에 보정 주의를 표시한다. 이 구간은 미래 월 예측이 아니라 같은 월의 지역 간 구조 차이를 반영한 진단용 split-conformal 구간이다.

## LLM 연결

LLM에는 전체 파일을 전달하지 않고 사용자가 선택한 지역 한 행과 선택 업종에 해당하는 신호만 전달한다. `final_signals`, 선택 업종의 `industry_signals`, `customer_composition`, `grocery_context`, `model_warnings`, `interpretation_boundary`를 정량 진단 컨텍스트로 사용한다.

LLM 답변에는 다음 원칙을 적용한다.

- 기대금액은 미래 매출 예측이나 적정 매출이 아니라 지역 구조를 반영한 비교 기준이다.
- BC카드 결제는 지역 전체 카드시장 또는 전체 매출이 아니다.
- 기대 대비 소비가 낮다는 사실만으로 정책 문제나 원인을 확정하지 않는다.
- 연령·성별 결제 구성은 원인 증명이 아니라 후속 점검 대상이다.
- 검색·정책 문서는 원인에 대한 확정 근거가 아니라 설명 가설이나 유사 정책 사례로 사용한다.

## 판정 범위

외식 전반 저조형은 외식 합계와 여러 외식업종에서 저조가 함께 나타난 경우다. 특정 업종 저조형은 외식 전체가 충분한 지역에서도 일부 업종의 절대 소비와 지역 내 상대적 소비가 모두 낮게 나타난 경우다. 외식 전반 저조형이라고 해서 구성 업종을 각각 특정 업종 저조형으로 중복 집계하지 않는다. `weak_industries`도 참고 목록이므로, 업종별 최종 신호는 반드시 `final_signals`의 `detection_type`과 `industry`로 확인한다.

비후보 지역은 문제없다고 판정된 지역이 아니다. 현재 기준에서 최종 신호가 확인되지 않은 지역이다. 외식 분석 대상 밖의 업종에도 이 후보 판정을 적용하지 않는다.

## 검증 상태

전달 데이터는 다음 조건을 확인했다.

- 251개 지역 키가 유일함
- 최종 후보 90개 지역
- 최종 신호 101개
- 모든 최종 후보가 지속성과 반복 안정성 기준을 통과함
- 외식 전반 저조형과 특정 업종 저조형의 구분 유지
- 한글 UTF-8 정상
- JSON의 NaN·Infinity 미포함
- 기존 넓은 후보 플래그 미사용

세부 검증 결과는 `validation_summary.json`, 원천 및 해시는 `manifest.json`에서 확인한다.
